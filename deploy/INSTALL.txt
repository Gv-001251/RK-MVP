==============================================================================
 RK Clinic LIS - installing on the lab machine
==============================================================================

 This machine becomes the LIS. It holds the database, talks to the analyzers,
 and serves the web interface to every other device in the clinic. Nothing runs
 in the cloud, so nothing works when this machine is off.

 Everything below happens once. Budget half an hour, most of it MySQL.


 BEFORE YOU START
 ----------------

 Windows 10 or 11, 64-bit, and an Administrator account.

 MySQL 8.4 LTS. Not 9.x. The 9.x line drops authentication plugins between
 releases and the app cannot log in to it. Download "MySQL Installer for
 Windows", choose Server only, and set a root password you will still have in
 ten minutes.

 The files sit next to the app, normally:

   C:\Program Files\RK Clinic LIS\rk-clinic-schema.sql
   C:\Program Files\RK Clinic LIS\setup-windows.ps1


 THE ORDER MATTERS
 -----------------

 1. Install MySQL 8.4 and confirm the service is running.

      Get-Service MySQL*

 2. Create the database, as root. This makes the tables, the staff logins, and
    the restricted account the app itself connects as.

      cd "C:\Program Files\RK Clinic LIS"
      mysql -u root -p < rk-clinic-schema.sql

    It prints "Setup complete: 55 tables in `rk_clinic`". If instead it stops
    with "STOP: this database already has tables", the database already exists
    and this file is not the right tool - it only builds a fresh one.

 3. Run the setup script in an Administrator PowerShell. Replace <account> with
    the Windows user the lab actually signs in as.

      powershell -ExecutionPolicy Bypass -File setup-windows.ps1 -ServiceUser <account>

    It writes the config, checks it can really reach the database, registers the
    LIS to start at boot, opens the firewall for the analyzers, and stops the
    machine sleeping. It will tell you if the database is unreachable rather
    than letting you find out later.

 4. Reboot.

 5. Check it came up. In a browser on this machine:

      http://127.0.0.1:3000/api/health     expect 200
      http://127.0.0.1:3000                the sign-in page

    Then from another PC on the same network, using this machine's IP:

      http://<this-machine-ip>:3000


 SIGNING IN
 ----------

 Five accounts exist: admin, doctor, nurse_pharmacy, technician, receptionist.
 Their passwords were generated when rk-clinic-schema.sql was built and printed
 once, to whoever built it. They are stored here only as bcrypt hashes and
 cannot be read back out.

 Change them from Admin > Users after the first sign-in. Anyone holding the
 installer holds the hashes.


 WHERE THINGS ARE
 ----------------

 Config      %APPDATA%\rk-clinic\.env.local
             Database password and the analyzer API key. Readable only by the
             service account and Administrators.

 Logs        %APPDATA%\rk-clinic\logs\
               service.log      the supervisor
               server.log       the web app
               hemat60.log      one file per analyzer bridge
               mispaplus.log
               afinion2.log
               maglumi800.log

 Tray icon   Shows each analyzer as a live tile. Right-click for the log folder.


 WHEN SOMETHING IS WRONG
 -----------------------

 Every page returns 500, or "Internal Server Error"
   The app cannot reach MySQL. Check the service is running, then check the
   MYSQL_USER and MYSQL_PASSWORD in .env.local against the CREATE USER line in
   rk-clinic-schema.sql. This accounts for nearly every failed install.

 The app never starts
   Look at service.log first. It records why each child process exited.

 An analyzer tile stays grey
   The instruments dial in to this machine, so the firewall rule and the network
   adapter address matter more than anything on the analyzer. Give the
   analyzer-side adapter 192.168.1.3. If the adapter is classified Public,
   Windows ignores the rules the setup script added:

     Set-NetConnectionProfile -InterfaceAlias "<name>" -NetworkCategory Private

 Windows warns about an unknown publisher
   Expected. The installer is not code-signed yet. More info, then Run anyway.


 TWO THINGS STILL WORTH DOING
 ----------------------------

 Back up. Every patient record lives on this one machine. Schedule a mysqldump
 to a drive or share that is not this machine, and check it restores.

 If staff need the LIS from outside the clinic, install Tailscale here rather
 than forwarding port 3000. Port forwarding puts a clinical system on the public
 internet, and sign-in over plain HTTP sends passwords in the clear.

   tailscale serve --bg https / http://127.0.0.1:3000
